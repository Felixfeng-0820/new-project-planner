Big Jump

One vague idea in, a verified product out. Hand your AI one sentence — it breaks the idea down, builds the whole project itself, checks its own work against a written acceptance list, and goes live at a public URL the moment your accounts are connected. Honestly — never by faking it.

View on GitHub How to install

For students like you

  • Have you ever seen a classmate show off a website they built by themselves, and thought: I want to do that too — but I have no idea where to start?
  • Do you want a project with a real URL that anyone can open — not a page that only runs on your own laptop?
  • Do you want to skip the toy tutorials and build something you can actually put on your resume?

If you nodded to any of these, this skill is for you. It turns your AI assistant into an autonomous builder: one vague sentence in, a deployed product out — and a short lesson after every module.

How it works

Runs the workflowYou say one vague sentence. It states its assumptions in one line, gives a direction, and lists the phases — each with a written definition of done — then starts building. No interviews, no "continue?" after every step.
Verifies before it claimsWalks the main path, tries weird inputs, reloads to prove persistence, watches the console for errors and 404s — plus a small repeatable check script every phase. A feature is done when its checks pass — not when a button reacts.
Teaches after each moduleA 4-line recap per phase: what was done, why this way, what you learned, and what was verified. Sparse output, no progress cards, then it moves on automatically.
Stops only for real blockersAn error it cannot fix alone, a missing secret or account, a choice only you can make, or a payment.
Deploys honestlyAsks your OK before creating a repo or deploying — auth is not permission. Then verifies the URL, or hands you a short checklist. Never claims a URL it did not open.
Protects your workNever resets or overwrites your uncommitted changes, never force-pushes; reverts only its own edits.
Adapts to your setupRuns the build itself when it has a terminal; in a plain chat it hands you files and exact commands instead — and never claims to have run what it couldn't.
Finds your directionNo idea what to build? A problem-hunting method and a 3-question picker turn "I don't know" into a product-shaped tool.

See the workflow in action

YouI want to build an AI tool that turns PDFs into summaries I can ask questions about.
Big JumpAssumption: single-page web app, one PDF at a time, no accounts. Direction: an "AI document reader" — upload → summary → ask questions. Plan: 6 phases. Starting now.

[Phase 1: creates the project and a git repo, commits.]

Phase 1 recap: we made the folder and a git repo. Why: git saves every version, so nothing can permanently break the project. You learned: a commit is a save point.

[Phase 2: deploys a hello-world page and reports the URL.]

Phase 2 recap: your first page is live at [URL]. Why: deploying early means a real URL exists from day one. You learned: deploying is putting files on a server so others can open them.

[Phases 3–6 run the same way — build, verify, commit, recap, continue — without asking.]
EndDone — the AI document reader is live at [URL]. It uploads a PDF, summarizes it, and answers questions about it. Upgrade ideas: (1) multi-file library, (2) a database for past documents, (3) accounts for your classmates. Want any of these, or should we start your next project?

Quick commands

  • /pause stop the auto-flow and wait for me
  • /next continue to the next step
  • /explain explain pasted code line by line
  • /review review my code, with reasons
  • /error troubleshoot my error step by step
  • /deploy walk me through putting it online
  • /showcase README, screenshot, demo link, resume bullet
  • /teach explain a concept, with exercises
  • /stack compare tech options and recommend
  • /ideas no idea what to build? run the direction finder
  • /retrospective summarize what I learned

Install

Codex — one command

Download the repository and run:

bash install.sh

Or copy manually so the file sits at ~/.codex/skills/big-jump/SKILL.md.

DeepSeek Harness

Put the big-jump folder into .dsh/skills or .agents/skills in your project, or into ~/.dsh/skills.

Claude Code / Cursor

Put the folder into the tool's skills directory (for example ~/.claude/skills/, or the .agents/skills project folder).

Use it

In a new chat, just say a vague idea, like "I want to build an AI tool that turns PDFs into summaries I can ask questions about." If the skill does not load automatically, say "Use the big-jump skill."
